# Project

This directory defines the high-level concepts, business logic and architecture of LeanElpi, a native Lean 4 implementation of ELPI λProlog, managed with the `tg` CLI. Run `tg check` to validate it.

Start with [[overview]], then [[architecture]] and the [[papers]].

- [[overview]] — goals, non-goals, milestones and how to read the graph
- [[decisions]] — accepted architecture decisions (type Decision)
- [[alternatives]] — rejected options and why (type Decision, status rejected)
- [[constraints]] — licenses, versions and mathematical facts nobody chose (type Constraint)
- [[glossary]] — domain terms with one exact meaning (type Concept)
- [[changes]] — the four OpenSpec changes, one per milestone (type Change)
- [[architecture]] — layers, module map, data flow, components and UML diagrams
- [[papers]] — paper-style explanations of how the system works
- [[code-ontology]] — shared vocabulary of intent types and typed edges between intent and code
